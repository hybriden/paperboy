# CLAUDE.md — working in this repo

Read this before changing or deploying anything.

## What this is
**Paperboy**, a headless CMS. pnpm monorepo:

- `apps/api` — Fastify v5 + `fastify-type-provider-zod` (one Zod schema per route → validation + serialization + OpenAPI 3.1). Management API (session + CSRF + RBAC) and Delivery API (GET-only, key-scoped).
- `apps/admin` — React 19 + Vite SPA: page tree, content areas, all-properties, live preview, visual on-page editing. react-router-dom, TanStack Query, Radix, @dnd-kit, TipTap.
- `apps/web` — Next.js 15 reference frontend (Draft Mode preview) on `@paperboycms/client`.
- `apps/mcp` — MCP server. Imports `@paperboy/db` and calls the **same functions** the API does, so it inherits RBAC, Zod, the no-leak chokepoint and audit.
- `packages/shared` — Zod schemas + types (single source of truth) + the AI provider.
- `packages/db` — Drizzle schema, forward-only SQL migrations, the query layer (all object-level authz, deny-by-default), seed.
- `packages/client` — `@paperboycms/client` on npm: typed Delivery SDK (`createClient`, lists/search/media, schema-driven render helpers, ETag cache), e2e-tested in `apps/api/test/client-sdk.test.ts`. Preview-token verification is the SEPARATE subpath `@paperboycms/client/preview-token` (WebCrypto; Node/Workers/Deno/Bun) because its first argument is `PREVIEW_SECRET` and the main entry must not reach it.
- `packages/preview` — `@paperboycms/preview` on npm: framework-agnostic on-page-editing bridge, zero dependencies. Single source of truth for the admin↔frontend postMessage protocol (`paperboy:edit/drop/add-block/rect/patch/focus`) and the `data-pb-*` DOM contract. The admin and `apps/web` import it; never re-declare message shapes.
- `evals/` — model-driven MCP usability eval. Every push runs it with the deterministic `--mock` driver (real tool calls, no paid API, so failures are real regressions); the weekly schedule runs a real model (`ANTHROPIC_API_KEY` secret). `ops/` — reference production backup/monitor scripts.

## First run
`./scripts/setup.sh` (or `.\scripts\setup.ps1`) writes `.env` with unique secrets and an admin password, then `docker compose up -d`. **Required:** the API refuses the `prod-…-please-override` secrets compose ships, and the seed refuses the published demo login, since both are committed in this public repo. Safe to re-run (never overwrites `.env`). A CI job runs this exact path in a clean checkout.

## ⚠️ Deploy safety (most important rule)
The compose `init` service runs migrate **+ seed**. `seed` TRUNCATEs and reseeds, wiping all data and regenerating IDs. The CLI is GUARDED: on a database that holds content it skips the wipe (still migrating) unless `FORCE_SEED=1`. The guard exists because a plain `docker compose up <svc>` pulling in `init` caused real data loss. A seatbelt, not an invitation.

- **Redeploy one service:** `docker compose up -d --no-deps --force-recreate <svc>`.
- **`docker compose start <svc>` also starts its `depends_on`, including `init` as the CONTAINER it was last created from.** A stale pre-guard init container re-ran an old unguarded seed this way and wiped production (2026-06-06; restored from backup). After pulling a new image, recreate init once: `docker compose rm -f init && docker compose up -d init`.
- **Migrations without reseeding:** they run on api boot, on a guarded-skip init run, or via `docker compose exec api pnpm --filter @paperboy/db migrate` (forward-only, idempotent, tracked in `_migrations`).
- **Deliberate reseed (wipes everything):** `FORCE_SEED=1 docker compose run --rm init`.
- Tests import `seed()` directly; it stays unguarded there.
- **Upgrading past the nginx removal** (no `admin` service; the api publishes 8090): the old admin container holds port 8090, so remove it BEFORE recreating the api. Its name is `<project>-admin-1` where project = the clone directory (`paperboycms-admin-1` for a default clone), so select by label from the compose directory: `docker rm -f $(docker ps -aq --filter label=com.docker.compose.service=admin --filter "label=com.docker.compose.project.working_dir=$PWD") && docker compose up -d --no-deps --force-recreate api`. Run `docker compose build api` first so the gap is only the restart. Cloudflare Tunnel/Caddy keep pointing at :8090; `/mcp` needs no edge change, the api forwards it.

## Ports & env
- admin **8090**, api **8091**, Postgres **5433** (host) → 5432. **No nginx:** the api serves the admin SPA (`ADMIN_DIST_DIR`, set in the image; `apps/api/src/admin-spa.ts`) and compose publishes it on both ports: one container, one origin, so the `__Host-` cookie and the CSRF Origin check need no proxy. Everything nginx did (strict CSP + `X-Frame-Options` on the entry point, no-cache index.html, immutable hashed `/assets/`, pre-gzipped bytes, gzip of API JSON via `@fastify/compress` (`compress.test.ts`), SPA fallback, `Disallow: /` robots.txt, no rate limit on assets) is pinned by `admin-spa.test.ts`; the CSP is ONE constant, `ADMIN_CSP`. The listen port honours a platform's `PORT` (`API_PORT` wins), so the image runs as-is on App Service / Container Apps / Cloud Run / Fly / Render. Mount a volume at `UPLOADS_DIR`, run ONE replica (rate limits and the retention/scheduled-publish tickers are in-process).
- **`web` (8092) is OPT-IN** (`docker compose --profile web up -d web`), like `mcp`. It pins the delivery contract in a second framework and is NOT the site a user builds on (that is the Astro starter, :4321). The quickstart CI job exercises the profile. **Upgrade gotcha:** `docker compose down` skips profiled services, so an existing `<project>-web-1` keeps running until removed (`docker compose --profile web down`).
- The seed sets the default site's **preview URL to `http://localhost:4321`** (override `SITE_PREVIEW_URL`). Empty, the side-by-side pane reads as broken.
- MCP **8093** (opt-in): `docker compose --profile mcp up -d --no-deps mcp` serves Streamable HTTP at `/mcp`. Clients sign in with OAuth or send a minted token as Bearer; `MCP_TOKEN` is only needed without OAuth. Default is stdio. **One-container hosts:** `MCP_EMBEDDED=true` makes the api spawn the MCP as a supervised child on `127.0.0.1:8093` and set `MCP_UPSTREAM_URL` to it (`apps/api/src/mcp-embedded.ts`, `mcp-embedded.test.ts`); setting both is refused at boot. **`PAPERBOY_SITE`** (slug or id) selects the site the server acts in; unset = Default, unknown = refuses to boot.
- **PGlite mode** (#124): `DATABASE_URL=pglite:///data/db` (or `pglite:memory`) makes the api start Postgres-in-WASM in-process behind a loopback socket (`packages/db/src/pglite.ts`), rewrite `DATABASE_URL` to it (the embedded MCP child inherits it), migrate, and seed ONLY an empty database (no init container, no wipe path). Our own socket server, not `@electric-sql/pglite-socket` (0.2.14 interleaves connections and stalls after an error): PGlite is ONE session, so a connection owns it until ReadyForQuery idle (`pglite-socket.test.ts`). The CI `pglite` job runs the whole API suite against it (`TEST_PGLITE=1` skips the one test that needs two real sessions) and boots the image from a volume. A separate `mcp` container can't share it.
- pnpm is at `~/.npm-global/bin`: `export PATH="$HOME/.npm-global/bin:$PATH"`.
- DB URL (host): `postgresql://paperboy:paperboy@localhost:5433/paperboy`.
- Secrets in `docker-compose.yml`/`.env.example` are dev defaults. Rotate `SESSION_SECRET`, `CSRF_SECRET`, `PAPERBOY_*_KEY`, `PREVIEW_SECRET` and the admin password before exposing.

## Auth model
- Browser: argon2id + opaque server-side session cookie (`__Host-paperboy_sid` when `COOKIE_SECURE=true`) + CSRF (synchronizer token bound to the session row, echoed in `X-CSRF-Token`, PLUS a fail-closed Origin/Referer check; no CSRF cookie; `apps/api/src/security.ts`) + rate-limit/lockout.
- **`COOKIE_SECURE=true` requires HTTPS.** http://localhost logins fail (cookie dropped).
- 2FA: **passwordless email + TOTP** (a 2FA account logs in with email → code). TOTP gates browser login only; service paths (`verifyLogin`) check the password.
- **Enabling 2FA requires the password** (`verifyReauth`, same as disabling). Login is passwordless once 2FA is on, so a stolen session could otherwise enrol its own authenticator and lock the owner out.
- **`MFA_SECRET` goes through the same placeholder guard as `SESSION_SECRET`/`CSRF_SECRET` (and `PREVIEW_SECRET`).** It is the AES-256-GCM KEK for `users.totp_secret` and the stored AI/stock keys; a shipped-constant value turns one leaked `users` row into a takeover (found live 2026-07-28, byte-for-byte the compose placeholder). Unset falls back to `SESSION_SECRET`.
- **The seed refuses the published demo credentials in production.** `admin@paperboy.test / Admin!Passw0rd`, the editor/author/viewer logins and the two seeded delivery keys are public constants; under `NODE_ENV=production` the seed demands real values and creates ONLY the admin. `ALLOW_DEMO_CREDENTIALS=true` opts a throwaway stack back in. A database holding data is skipped before this runs.
- **The preview secret never reaches the browser.** The admin fetches a short-lived signed token (`GET /manage/preview-token`) and passes `?pbt=`; the frontend verifies it with the same `PREVIEW_SECRET`, set on BOTH api and web. `?pb=<secret>` still works server-side. **Frontends must not hand-copy the verification:** it ships as `@paperboycms/client/preview-token`, and `client-preview-token.test.ts` pins the signer (shared/node:crypto) to the verifier (client/WebCrypto), since drift kills preview or leaks drafts silently. Never reintroduce `VITE_PREVIEW_SECRET`: Vite inlines `VITE_*` and `/assets/` is unauthenticated, so it published the secret (verified live).
- MCP: a **token** (Settings → Agent access, admins only; `MCP_TOKEN` env) or email+password; authenticates AS a user and inherits its RBAC.
- **MCP tokens are SITE-SCOPED** (migration 0028, `mcp_token.site_id`), minted against the active site like a delivery key (`verifyMcpToken` returns `{userId, siteId}`, like `verifyDeliveryKey`). The scope is a CREDENTIAL-level cap: it sets the default site and bounds every per-call `site`; a scoped token asking for another site is refused. `NULL` = every site (what existing rows got; what the "Every site" checkbox mints). The cap lives in a PER-REQUEST scope (`AsyncLocalStorage`, `apps/mcp/src/server.ts`), not a module variable, so one HTTP server serves a scoped and a cross-site token at once (`mcp-http-transport.test.ts`). Tools that change what EVERY site shares (users/roles, content types, type templates) and `list_audit` require a cross-site token (`requireCrossSiteToken`): roles are global, so a one-site Admin token could otherwise mint an every-site Admin (`mcp-token-scope-instance-tools.test.ts`).
- **A token is minted as the SIGNED-IN user** (Settings → Agent access asks only for a name and a scope) and inherits their roles and section scopes, so an agent never exceeds its creator. No password re-auth (`POST /users` can already create an Admin without one). `POST /manage/mcp-tokens` accepts an optional `userId` (`user.manage` only, not in the UI) for service accounts.
- **Remote MCP clients sign in with OAuth 2.1** (MCP authorization spec). The API is the authorization server (`apps/api/src/routes/oauth.ts`, `packages/db/src/oauth.ts`, migration 0029); the MCP server is the protected resource. Discovery (RFC 8414 / 9728), dynamic client registration, code + PKCE (S256 only), resource indicators, rotating refresh tokens, all stored hashed. **Consent picks the site** on the admin's `/oauth/authorize` page after login + 2FA: site-wide readers (Admin/Editor/Viewer) may pick any site or "every site"; a section-scoped Author only sites they hold a section in. `createAuthorizationCode` re-checks server-side. A grant carries the same `siteId` cap as an `mcp_token`. Config: `PUBLIC_URL` (issuer; default `CORS_ORIGIN`), `MCP_PUBLIC_URL` (resource; default `{PUBLIC_URL}/mcp`), on both api and mcp. The api serves `/.well-known/oauth-*` and forwards `/mcp` to the mcp service (`MCP_UPSTREAM_URL`, a streaming byte pipe in `apps/api/src/mcp-forward.ts`, exempt from rate limit; compose default `http://mcp:8093`), so one domain works (`mcp-forward.test.ts`). Connections are listed and revocable in Settings → Connected apps (your own; everyone's under Settings → Agent access for `user.manage`). Pinned by `mcp-oauth.test.ts`, `mcp-oauth-http.test.ts`, `e2e/oauth-consent.spec.ts`.
- **In HTTP mode every request acts as the user whose token it presents** (OAuth or any user's `mcp_token`), re-resolved per request. An MCP session is bound to the user who opened it (another user's token on that session → 403). `mcp-http-transport.test.ts` pins this.
- **Revocation is immediate in HTTP mode:** the bearer is resolved through the DB before any compare against the boot `MCP_TOKEN`, and `AccessContext` is re-resolved per request. A stdio process authenticates once at boot. An env-only `MCP_TOKEN` with no DB row still works (rotate by restart).
- **Agents upload through an UPLOAD LINK** (migration 0030, `upload_link`). A remote server can't read the agent's disk and base64 costs ~100k tokens per image, so MCP `create_upload_link` mints a 15-minute hashed `upl_…` token and the agent curls files to `POST /api/v1/uploads` with it as Bearer (`apps/api/src/routes/uploads.ts`). The link acts as the minting user in the minting site, roles re-resolved per request; the route never reads the session cookie. `upload_asset` takes a public URL (`fetchPublicFile`: webhook egress guard per hop, pinned connect, manual redirects, 5 MB streamed cap) or base64. Every path, admin included, ends in `storeUploadedAsset` (packages/db/src/uploads.ts): one sniff, one size cap. Route cap: 20 files × 5 MB. `mcp-upload.test.ts`.
- **MCP tools are listed per ROLE.** Each `tool()` declares the one permission it needs (`null` = anyone signed in); `buildServer` registers only the tools the session's user holds, so an Author never sees user/key/webhook/audit tools, and a call to an unlisted tool gets the SDK's "Tool X not found". The wrapper re-checks that permission on every call because the list is fixed per session while roles are re-resolved per request (a demoted user gets `Missing permission: …`). Site-scoped tokens still SEE instance-wide tools and get the self-teaching "needs an every-site token" refusal (`mcp-token-scope-instance-tools.test.ts`). Every tool must carry a ≥80-char description, a description on every parameter and annotations — `mcp-parity.test.ts` enforces it (Glama's TDQS reads exactly that).
- **MCP tools are grouped into TOOLSETS** (`TOOLSETS` in apps/mcp/src/server.ts): `content` (the default listing, 25 tools), `delivery`, `schema`, `redirects`, `experiments`, `forms`, `admin`. Chosen per server (`PAPERBOY_TOOLSETS`) or per HTTP connection (`/mcp?toolsets=…`, fixed for the session it opens; `all` = everything); an unknown name refuses (boot exit / 400). A session lists `toolsets ∩ role`; a call to a role-permitted tool outside its toolsets, or to a retired name (`RETIRED_TOOLS`: merged or renamed), answers with how to reach it instead of "not found" (`answerUnlistedTools`, a wrapper over the SDK's tools/call handler). **A new tool must be added to exactly one toolset** (registration throws otherwise). Content-set descriptions shouldn't name tools outside it. Tools over instance-wide data (`INSTANCE_WIDE_TOOLS`) take no `site`. The test suite runs with `PAPERBOY_TOOLSETS=all` (vitest `env`); `mcp-toolsets.test.ts` pins the real default. Cut from 64 because Glama's TDQS scores 50+ tools as an "extreme" count (#120, #121).
- **`delivery_*` MCP tools need `content.read`; the preview perspective also needs site-wide read.** The delivery chokepoint is key-scoped, not section-scoped, so a section-scoped user with `preview:true` would otherwise read every draft in the site.

## Content model
- Content types are **data** (`content_type` table). Kinds: `page` / `block` / `global`.
- **PARTS (`nestedOnly`)**: a block type only ever nested inside another (a Form's field blocks). `allowedBlocks` states the rule from the container's side and defaults to "any block"; this flag is the other half. A part is left out of the palette's no-allow-list fallback, the reuse picker and the empty-types count, and gets a "Parts" tab. It IS listed in a content area's `allowedBlocks` picker and is otherwise a normal block (shareable, versioned, localized, RBAC'd, MCP-editable). Use `generalBlockTypes()` (packages/shared) for "any block"; don't re-derive `kind === "block" && !nestedOnly`. Deliberately not a fourth `kind` (kind carries storage semantics). Migrations 0024 (form fields) and 0025 (accordion/FAQ/link items) flag the built-ins, since template instantiation is create-only.
- **Child ordering is declared on the container** (`content_item.child_sort`): `manual` (drag order; new children append at max+1) or `name` | `createdAt` | `data.<field>`, `-` prefix descending. Admin tree and delivery's default list order share one comparator (`sortByRule`, packages/shared); explicit `?sort=` wins; non-public `data` fields never order a public list. Set via tree right-click → Sort children… / `POST /content/:id/child-sort`.
- Content areas hold ordered block instances, inline (page-local) or shared (reference). Fields: text, markdown, richtext (TipTap JSON), boolean, number, datetime, select, link, image, reference, contentArea (+ legacy media). Image/media values are asset documentIds; URLs and paths are rejected at write.
- Delivery is a **single read chokepoint** with a `perspective` (published | preview). Public key → published only; preview key → drafts. Private fields never reach output. Don't add read paths that bypass it.
- **Delivery batches its lookups per response** (`DeliveryCtx` in packages/db/src/delivery.ts): all content types in one query, the referenced documents/assets of each graph level in one (`primeReferences`), a page's ancestor chain in one recursive query (`primeAncestors`), and types/locales/SiteSettings started together (`warm()`). On a managed database every query is a network round trip (a real page went 68 → 13 queries; ~2× faster at 2 ms latency). A primer must use the SAME filter as the single lookup it feeds, so output stays byte-identical. `delivery-query-count.test.ts` fails if query count grows with the number of blocks/images.
- **Delivery READS are GET-only; form submissions are the one anonymous WRITE**, with their own chokepoint (`submitForm`, `packages/db/src/forms.ts`; route `apps/api/src/routes/submit.ts`), deliberately not in delivery.ts. That route must never read a session cookie: "no CSRF needed" is only true while it has no ambient authority; `forms-submit.test.ts` asserts a cookie-bearing request is anonymous. Don't add public write paths without the same treatment.
- Delivery items and inline blocks expose **`fieldTypes`** (declared type per public field) so frontends switch on schema, not values. Frozen contract.
- **SEO contract**: fields declare a `seoRole` (title/description/image/datePublished/…) and/or `schemaProp` (dot-path schema.org property, e.g. `offers.price`); the type carries a `schemaType`. Delivery computes a normalized `seo` block (meta/canonical/robots/OG/Twitter + per-`@type` JSON-LD + breadcrumbs) on every PAGE item, **post-sanitize** so a private field can't leak; preview is always `noindex`. The per-`@type` catalog and `SEO_CONVENTION` live in packages/shared so the type-editor checklist and delivery can't drift. `delivery-seo-contract.test.ts`.
- **Structured data is set up in the CMS, not in frontends.** A **content area with a `schemaProp`** becomes the list of nodes its blocks make (a block whose type has a `schemaType` is a node; one without is transparent, so FAQ topics hand their questions up), giving `mainEntity` Question/Answer pairs and offices as `department`. A **global with a `schemaType`** is delivered with its own `jsonLd` (a SiteSettings typed `Organization` is the site's identity). **Blocks with a `schemaType` on a page** come back as `seo.jsonLdParts`. An author matching the identity's name/legalName/alternateName (or the site name) is that organisation, not a Person. A CreativeWork page's `dateModified` is the delivered version's date (sitemap lastmod) unless a field carries the role. `SCHEMA_LIST_PROPS` (`sameAs`, `knowsAbout`, `keywords`) split a text field per line/comma. The type editor shows the @type for every kind and a per-field schema.org box. `delivery-structured-data.test.ts`.
- **Public files**: robots.txt / sitemap.xml / llms.txt / security.txt are GENERATED by delivery (`GET /delivery/{robots.txt,sitemap.xml,llms.txt,security.txt}`, built on `GET /delivery/pages`) and PROXIED by the frontend (apps/web route handlers are the reference). Config per site (`site.canonical_base_url` + `site.seo_files`, migration 0021; Settings → Site → Public files; `POST /manage/site/public-files`). Builders in packages/shared/src/public-files.ts. noIndex pages are excluded from sitemap/llms; llms descriptions honour field visibility; security.txt Expires is a rolling 180 days; absolute URLs use `{canonicalBaseUrl}/{locale}{urlPath}`, or no prefix for the default locale when `site.locale_prefix` is `except-default` (Settings → Site → Language in URLs). A frontend with another scheme builds its own from /delivery/pages. The admin origin serves a static `Disallow: /` robots.txt.
- **Type templates**: reusable ContentTypeDef recipes (`type_template` table + REST + MCP + Settings → Type templates). A BUILT-IN library ships in code (`BUILTIN_TYPE_TEMPLATES`, packages/shared/src/type-templates.ts; read-only, names reserved; duplicate to customise), invariants in `shared-builtin-templates.test.ts`. Instantiate refuses to overwrite without `updateExisting: true`; `withBlocks: true` also creates referenced block types (recursive). Export/import (`GET /type-templates/export`, `POST /type-templates/import`: versioned envelope, per-template skip reasons, built-ins skipped). Admin: "New content type" opens a gallery (blank / customize / use-as-is).

## Redirects
Per-site rules that keep link equity when URLs change. Research: `docs/plans/2026-10-15-redirects.md`.

- **Rules live in the CMS, the frontend applies them.** `GET /delivery/redirects` serves one manifest per site (body-hash ETag); frontends match with `matchRedirect` from `@paperboycms/client`. It exists twice (`packages/shared/src/redirects.ts` for Test a URL and chain checks, and the client) and `client-redirects.test.ts` pins them together. Don't hand-roll matching.
- **A rule fires ONLY where no published page answers:** fetch the page first, consult the manifest on 404. A rule can never hijack a live page; one whose source IS live is reported `shadowed`.
- **Page targets, one hop.** A target may be a page (documentId + locale), resolved to its LIVE url at manifest build, so moving it again never chains. A typed path a published page answers is STORED as that page. At write, a redirected path target collapses to the final destination, rules pointing at the new source are re-pointed, loops are refused with a self-teaching 422 (`redirects.test.ts`).
- **Automatic 301s**: publish, scheduled publish and re-parenting run inside `trackUrlChanges`, which diffs the subtree's published URLs and records each change (origin `auto`). Renaming back removes the stale auto rule; an editor's own rule is never overwritten. Tracking errors are logged, never thrown.
- **`site.locale_prefix`** (`always` | `except-default`, migration 0031) turns (locale, urlPath) into the requested path. Redirect targets AND sitemap/llms follow it; default `always` matches the reference frontend.
- **`POST /delivery/traffic` is the SECOND public write**, built like form submissions: own module (`routes/traffic.ts`), PUBLIC key only (preview key → 403, no cookie read), rate-limited per key. Counts rule hits and logs 404 paths (path only, no IP/UA, scanner noise dropped by `isNoise404`), 90-day retention + 2,000-path cap per site, swept hourly.
- **No regex.** Exact paths and a trailing `/*` prefix. Case and trailing slash normalized (`normalizePath`); query passes through unless `keepQuery` is off.
- Permissions: read `content.read`, write `content.publish`, audited. MCP: `list_redirects`, `create_redirect`, `update_redirect`, `delete_redirect`, `test_redirect`, `list_not_found`.

## A/B experiments
Editors test one content area of a page against up to three alternatives (#125). Decisions: `docs/plans/2026-10-22-ab-testing.md`. Code: `packages/shared/src/experiments.ts` (assignment, statistics), `packages/db/src/experiments.ts` (rules), `apps/api/src/routes/experiments.ts`. Tests: `experiments.test.ts`, `shared-experiments.test.ts`.

- **Words:** an experiment has VERSIONS A–D ("arms" in code). "Variant" means a language branch; never use it for this in UI text.
- **Own tables** (migration 0033: `experiment`, `experiment_arm`, `experiment_stat`), never a dimension on `content_version`. Version A is the page's PUBLISHED area and stores no blocks; B–D pass `prepareAreaBlocks` (packages/db/src/content.ts), the same coercion/validation/allowed-blocks verdict as the area itself. One live (running or paused) experiment per area (partial unique index). A running experiment can't be edited: pause first.
- **Delivery ships the versions, the frontend picks.** A page's running experiments ride on the item as `experiments` (additive; the area stays the control). Every version goes through `sanitize`, SEO is computed from the control, and the experiment's `cv` folds into the page's so start/pause/end change the ETag. Preview also ships draft/paused ones (with `status`). Assignment is `assignArm` (FNV-1a, 10 000 buckets); no visitor key → A, robots included, the user agent is never read.
- **Counting is the third use of `POST /delivery/traffic`** (`exposures`, `conversions`; public key, no cookie, per-day counts in `experiment_stat`, no visitor id/IP/UA). Unknown, ended or mismatched events are ignored and counted, never an error. A form submission may carry `experiments: [{id, arm}]` → a conversion for `goal: "form"`; nothing is stored on the submission.
- **No winner before the planned sample size** (`experimentVerdict`, rule 1); a sample ratio mismatch withholds the leader. `estimate` gives exposures per day since the start and, with a plan, `estimateDaysLeft` (null without traffic: no number is better than an invented one). Ending with a winner writes its blocks into the area via `updateContent` (draft), optionally publishing. Losing versions are kept.
- **Admin** (`ExperimentPanel.tsx`, Settings → Experiments, dashboard section, preview version picker via `?pbab`): End flushes the editor's pending autosave first (`beforeEnd`, like publish), or the later autosave was refused as a 409 and the edits were lost (#146). Publishing a page with a running experiment asks first: version A IS the published area. Start/Resume confirm with `tone: "primary"` (useConfirm defaults to danger). `e2e/experiments.spec.ts`.
- **The ticker** (`runExperimentTicker`, every minute) ends experiments at `ends_at` or when the page is trashed, unpublished, moved site, or the area leaves the type; daily counts older than 400 days are swept. Start/pause/end announce `delivery.changed` `experiment`.
- **Admin:** the area header's "A/B test this area" / status badge opens `ExperimentPanel` (versions B–D edited with the area's own `ContentArea`); the publish menu has "View experiment"; the preview's version picker appends `&pbab=<id>:<arm>` and makes that frame read-only like a borrowed page; Settings → Experiments lists them (`?experiment=<id>` on the editor URL opens one); the dashboard shows running, overdue and needs-review ones. `e2e/experiments.spec.ts`.
- **MCP:** the `experiments` toolset (`list_/get_/create_/update_/start_/pause_/end_experiment`; `mcp-experiments.test.ts`), not in the default listing. `evals/mcp-eval.mjs` has an `ab-test` journey (a scenario may set `toolsets` and bring its own `check` when it makes no page).

## Forms and submissions
Forms are **content** and submissions stay in this instance's Postgres, which no headless CMS surveyed does. Research: `docs/plans/2026-08-22-forms.md`.

- **A form IS content**: the built-in `Form` block (kind `block`, so a shared block with its own documentId) holds settings and a `fields` area of one block per question (`FormTextField`, `FormEmailField`, `FormTextareaField`, `FormNumberField`, `FormDateField`, `FormSelectField`, `FormRadioField`, `FormCheckboxField`, `FormConsentField`, `FormStaticText`), all in `BUILTIN_TYPE_TEMPLATES`. Versioning, draft/publish, localization, RBAC, preview and MCP come free. A Form must be placed **shared**: submissions post against its documentId.
- **One authority for the contract**: `packages/shared/src/forms.ts`. `formSpecFrom()` normalizes a Form into the spec delivery attaches as `content.form` (schema, never markup); `submissionSchemaFor()` compiles the validator from the **current published** definition. Never validate a submission anywhere else.
- **Unknown answer keys are REJECTED** (422), not stored or dropped. Field-level messages come back keyed by field (WCAG 3.3.1), using the editor's own error copy when written.
- **Spam**: a honeypot hidden from sight AND assistive tech, plus a minimum fill time, on by default. The honeypot input is `readOnly` (`honeypotAttrs`) because WebMCP offers every other named control to an in-browser agent, aria-hidden and display:none included (verified in Chromium 156); an agent filling it would lose a real enquiry behind a 202. Frontends make a form a WebMCP tool with `formToolAttrs(spec)`, never with `toolautosubmit` (#119). A drop returns **202 like a success**; the reason goes to the audit log. Turnstile is opt-in per form (`TURNSTILE_SECRET_KEY`); a form asking for a challenge with no secret REFUSES.
- **Storage**: `form_submission` (migration 0022). `field_snapshot` freezes each field's label+kind as answered (for a consent checkbox that IS the evidence). IP/user-agent stored **only** when the form opts in.
- **Retention is real**: `expires_at` at insert (form → instance → `SUBMISSION_RETENTION_DAYS`, default 365), swept hourly by `runSubmissionRetention` from app.ts. Never ship a compliance setting that silently does nothing. ⚠️ Nightly `pg_dump` contains visitor PII, so erased data survives in backups for the rotation window; a data-subject response must say so.
- **Permissions**: `submission.read` / `submission.manage` (Admin + Editor only). Exports and erasures are audited.
- **Notification** is `form.submitted` on the webhook pipe. Paperboy has **no mail transport**; if one is ever added, `From:` must be our own domain with the submitter in `Reply-To`, and header values stripped of CR/LF at one chokepoint.
- **Deliberately not built** (forms plan §9): file uploads, conditional logic, multi-step, payments, autoresponders, a bespoke designer.

## Webhooks
Site-scoped, HMAC-SHA256 (`x-paperboy-signature: sha256=…`, event in `x-paperboy-event`), SSRF-guarded, logged in `webhook_delivery`, fire-and-forget. An empty event list means every event EXCEPT `form.submitted` (PII must be asked for by name).

- `content.published` / `content.unpublished` from every surface (REST, MCP, scheduler).
- **`delivery.changed`** `{siteId, reason, documentId?}`: delivered output changed WITHOUT a publish. Reasons: `moved`, `sorted`, `trashed`, `variant-deleted`, `start-page`, `site-settings`, `asset`, `redirects`, `experiment`, `content-type`, `locale` (the last two are shared, so every site hears them). Lets a frontend cache purge on webhooks alone. Announced from the query layer (`announceDeliveryChange`), so MCP fires it too. Restore from trash does NOT announce (the page comes back unpublished). `webhook-delivery-changed.test.ts`: a new write path that changes delivered output must announce, and be added there.

## AI (the writing assistant)
- One provider seam in `packages/shared` (`chat()` + `postAnthropicMessages`/`postOpenAiChat`), two dialects: **Anthropic** or any **OpenAI-compatible** endpoint (OpenAI, OpenRouter, Groq, Ollama…; `max_tokens` retries as `max_completion_tokens`). Config (provider/key/model/baseUrl/reasoningEffort) is instance-global (Settings → AI provider), as is the agentReview gate (Settings → Agent access). reasoningEffort maps per dialect, degrading to none when the endpoint rejects it: openai `reasoning_effort` → GLM-style `thinking:{type}`; anthropic `output_config.effort` (minimal → low) plus adaptive thinking at medium/high (never `budget_tokens`: current models 400 on it). The agent echoes an Anthropic turn back VERBATIM (`ModelTurn.raw`), thinking blocks included; rebuilding it from text + tool_use dropped them (#93). `resolveAiRuntimeConfig` (packages/db) is the ONE resolver API and MCP share. **Key/provider/baseUrl resolve as a UNIT (DB wins, else env), and a key is bound to the provider it was saved under**: switching provider clears the key; env keys are vendor-bound (`ANTHROPIC_API_KEY`→anthropic, `OPENAI_API_KEY`+`OPENAI_BASE_URL`→openai, `AI_PROVIDER` picks when both set). Security rule: an admin-set baseUrl must never receive another vendor's key. `POST /manage/site/ai/test` does a REAL roundtrip. Surfaces: writing assistant (improve/rewrite/draft/variants; UI label "Writing assistant"), translate (incl. richtext), vision alt text (`POST /ai/alt-text` sends the image bytes, site-partitioned), schema.org suggestions, "Build from brief" agent (`apps/api/src/agent.ts`), MCP `assist_writing` (uses the stored config, not just env).
- **No key → model-requiring tasks REFUSE** with a self-teaching `AiUnavailableError`; never echo the input as a result (rule #1 below). Only meta_title/meta_description/summarize keep truncation fallbacks, labeled `provider: "fallback"`. The admin disables those entry points with an honest hint.

## Multisite
Sites are partitioned by `content_item.site_id` (migration `0012_sites.sql`; pre-multisite data backfilled into the fixed `'site_default'` site, also the column DEFAULT). Decisions: **D1** per-site delivery keys (`delivery_key.site_id`; `verifyDeliveryKey` → `{type, siteId}`); **D2** media per-site (`asset.site_id`), content types, locales and users SHARED; **D3** one lossless Default site.

- **The partition is enforced in the two chokepoints, deny-by-default.** Management: `AccessContext.siteId` gates `loadAuthorized`/`loadAnyState` (a cross-site doc reads as not-found, even for an admin) and every broad scan (`getTree`, `listBlocks`, `listPages`, `searchContent`, `listTrash`, `emptyTrash`, `listAssets`). Delivery: `DeliveryCtx.siteId` confines `ctx.item()` (so the whole reference graph stays in-site) plus the direct `content_item` scans and asset resolution.
- **Active site** comes from the `x-paperboy-site` header (admin site switcher); unknown/absent → Default. Slug uniqueness is per-site. `createContent` children inherit the parent's site; roots take the active site.
- **Per-site setup** (migration `0013`): preview URL and start page live on `site`; delivery keys are minted/listed/renamed/revoked per active site. Settings → Site edits the active site and manages sites. `deliveryStartPage` serves the requesting site's own start page. AI config stays instance-global.
- **Roles are per site or every site** (#130, migration 0032): `user_role.site_id` NULL = every site (every pre-0032 row, so upgrading changes nobody). `getAccessContext` resolves the active site's roles plus every-site ones; a ONE-SITE role never grants `INSTANCE_PERMISSIONS` (`user.manage`, `contenttype.manage`, packages/shared), so a one-site Admin runs their site (content, keys, webhooks, Site → General via `site.manage`, its users via `siteuser.manage`, its audit log) but not users/sites/content types/AI/tokens. A site Admin adds users to THEIR site only (an existing email without a password = add that account), edits only roles/sections held there, never the account (name/email/password/delete), never an every-site role. The switcher and OAuth consent list only sites the user holds a role in; a request for a site they can't open falls back to their home site. `audit_log.site_id` files site actions (instance actions in `INSTANCE_ACTIONS` stay NULL). The last-Admin guard counts every-site Admins. `site-roles.test.ts`.
- Closed gaps: MCP site pinning (2026-09-09, `PAPERBOY_SITE` + per-call `site`, see below) and reference-target validation (2026-08-31: a missing, trashed, cross-site, wrong-kind or wrong-type `ref` is refused with a 422; `reference-target-validation.test.ts`).
- **One MCP server reaches EVERY site**: `PAPERBOY_SITE` only sets the default; every per-site tool takes an optional `site` (slug or id; instance-wide tools have none); `list_sites` reports what exists and which is active. The per-call context is AsyncLocalStorage-backed (`callCtx`, `ctx()` in apps/mcp) so two overlapping calls naming different sites can't bleed. An unknown `site` is a self-teaching ERROR, never empty results (an empty list reads as "this site has no pages", the original bug in a different hat). Found live: every tool returned the Default's content for a second site. `mcp-site-selection.test.ts`.

## Agent-API design rules (MCP & write endpoints)
Every rule traces to a real agent run that broke. Do not regress them.

1. **Never garbage-in-success-out.** Coerce only when meaning-preserving; otherwise REJECT. A destructive write that returns success gaslights the agent into a retry loop (a TipTap doc sent to a markdown field was flattened without separators, persisted, "success", the agent looped 9× and aborted).
2. **Errors must be self-teaching.** Name the field, the expected JSON shape, and a copyable example (`fieldFormatHint` / `formatDataValidation`). The error text is the only context an agent reads mid-loop.
3. **All tolerant coercion lives in ONE chokepoint**: `coerceFieldValue` (packages/shared), applied server-side in `updateContent` so API, MCP, agent and admin all pass through it (the admin never coerces locally); `update-ergonomics.test.ts`. Mistakes it absorbs, each from a real run: self-keyed wrap `{field: v}`, locale-map wrap `{en: v}`, TipTap doc → Markdown / plain text, string → TipTap doc, single block → array, resolved asset object → documentId, out-of-schema richtext → normalized. Add new mistakes HERE, with a test.
   **It reaches the WHOLE document.** `coerceData` takes a `BlockTypeResolver` and recurses into content-area `inline` block data (depth-capped), because it once stopped at the top level and a block's `richtext` kept raw Markdown (persisted, 200, rendered blank). `shared-coerce-blocks.test.ts` + `inline-block-coercion.test.ts`. Strict validation of `inline` against the block's schema and rejection of an unknown `blockType` happen at every level (`contentAreaSchemaFor` in shared + `assertPlacement` in db; `unknown-blocktype.test.ts`). **Unknown TOP-LEVEL keys are refused at write** (#79, `assertKnownKeys` in `prepareDraftData`; `unknown-data-keys.test.ts`): a 422 naming the key, the closest field and the type's fields. Keys already stored ride along (the schema root stays `passthrough()` so old rows read and publish), and `copy_variant` carries only declared fields.
4. **Offer flat single-string params for long content** (`set_field`). Long strings nested in record params get mangled to `{}` by some clients' JSON repair. Steer to it in tool descriptions and errors.
5. **Safe defaults over sharp semantics.** `update_content` merges by default (a full replace drops required fields and bricks the next publish). Pages auto-slug from their name.
6. **Every failed run leaves a trail.** MCP tool errors log to stderr WITH truncated args (stdout is JSON-RPC in stdio mode); every MCP write audit-logs like the API (`ip='mcp'`). Two incidents were undiagnosable because errors only travelled in-band.
7. **Annotate the schema for agents.** `list_content_types {name}` returns `valueFormat` + `valueExample` per field.

## ⚖️ Bugfix law: failing test first
Every bugfix STARTS with a test that reproduces the exact reported failure: same flow, same surface (API/MCP), same inputs. Run it and confirm it FAILS on the unfixed code. Then implement, and the same test goes green in the same change. No repro, no fix.

## Testing
- API: `pnpm --filter @paperboy/api test` (Vitest + a real Postgres test DB).
- **Coverage is enforced.** `pnpm test:coverage` runs the API suite with v8 coverage over `apps/api/src` + `packages/db/src` + `packages/shared/src` (`allowExternal: true` counts the two out-of-root packages). CI runs this, so the thresholds in `apps/api/vitest.config.ts` gate the build. Baseline (2026-08-13, after the `@vitest/coverage-v8` 2→4 instrument change): **92.15% lines, 88.16% statements, 88.28% functions, 77.55% branches**; thresholds 91.5/87.5/87.5/77. **Ratchet only**: raise as coverage rises, never lower to go green (re-baseline an instrument change with the evidence in the config comment).
- CI also runs `packages/client`, `packages/preview` (both published) and `apps/web`. `prepublishOnly` runs a package's tests before it can ship.
- **Contract-freeze layers** (`apps/api/test/`): `shared-*.test.ts` are pure unit/property tests of packages/shared; `delivery-contract` + `openapi-snapshot` pin delivered JSON shapes and the API surface as snapshots. A failing snapshot means you changed a PUBLIC CONTRACT: review the diff and update deliberately in the same commit, never blind `--update`. `mcp-parity` spawns the real stdio MCP server and locks the tool surface, write parity and error shapes.
- e2e: `pnpm --filter @paperboy/admin test:e2e` (Playwright + axe). Against a live deploy: `ADMIN_URL=https://<host>` (needed because `COOKIE_SECURE` breaks http login). Don't run the data-mutating suite against an instance you care about.
- Always `pnpm -r typecheck` before deploying.
- Lint: `pnpm lint` runs **oxlint `--type-aware`** (needs the `oxlint-tsgolint` dev dep, in the lockfile). Every rule is **error**, no downgrades or exemptions. Covers type-aware async-correctness (`no-floating-promises`, `await-thenable`) AND a11y. Conventions: floating promises get `void` (don't make handlers async); `unknown` content values stringified via a local `scalarToString`/`asText`/`rtScalar` helper (objects → `""`, never `"[object Object]"`); `autoFocus` replaced by `useRef` + mount `useEffect`. ## Code quality
Walk this ladder top-down and STOP at the first rung that applies:

1. **Does this need to exist?** No: skip it (YAGNI).
2. **Stdlib does it?** Use it.
3. **Native platform feature?** Use it.
4. **Installed dependency?** Use it.
5. **One line?** One line.
6. **Only then:** the minimum that works.

Simple and readable over clever. One responsibility per file and function. Explicit names. Small, composable functions. No hidden side effects. Maintainability first.

- Migrations are forward-only; add a new numbered `.sql` in `packages/db/migrations/`.
- **Admin look** (#149, tokens in `apps/admin/src/index.css`): calm and neutral, the space even. One grotesk; the serif is the wordmark only (`.wordmark`).
